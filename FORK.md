# Telegram Android — подготовка форка

Upstream: https://github.com/DrKLO/Telegram

Fork: https://github.com/AndreyZlobin/Telegram

База: Telegram 13.2.2 (7303), commit `21f7d109da6ab3506c9e9577f98c6a38771ab335`.
Ветка `setup/android-build` сохраняет базовую сборку. В `feature/tglock` встроен
TGLock 2.0.0-beta.19: переключатель «Включить TGLock» на экране настроек прокси.
Экран доступен также по значку прокси справа вверху на экране ввода телефона.

Прокси выключен по умолчанию. При включении Rust-ядро запускается внутри процесса
Telegram и слушает только loopback на свободном порту. MTProto-секрет генерируется
для этого процесса; в журнал не выводится. Сохранённый обычный прокси не изменяется.
При отключении восстанавливается прежнее соединение. Переключатель общий для всех
аккаунтов; выбор сохраняется между перезапусками, а listener запускается заново.
Ротация обычных прокси при включённом TGLock приостановлена.

Отдельное приложение, VPN, root и новые Android-разрешения не нужны. Ядро живёт
вместе с процессом Telegram; самостоятельного фонового сервиса нет. Это не
обещание постоянной работы после принудительной остановки приложения Android.
TGLock использует свои WebSocket/TCP маршруты; работоспособность зависит от сети.
Пользовательский Cloudflare Worker в этой версии интерфейса не настраивается.
Звонки TGLock не туннелирует.

Проверено 16 ноября 2026: сборка ARM64 debug APK успешна. Проверены целостность
APK, наличие только ARM64 нативных библиотек и подпись APK v1/v2.
Package ID: `org.telegram.messenger.beta`, версия `13.2.2` (73039).

## Сборка для телефона

```sh
./scripts/build-phone.sh
```

Результат: `build/fork-phone/telegram-tglock-arm64-v8a.apk`. Отладка приложения,
DEBUG_VERSION и DEBUG_PRIVATE_VERSION выключены. Для быстрого обновления сохранены
пакет `org.telegram.messenger.beta` и прежняя подпись; название Telegram Beta остаётся.
Используется задача Gradle AfatDebug без минификации, но Test Backend отключён
во всех сборках: переключатели удалены, нативное переключение запрещено. Сохранённая
тестовая сессия сбрасывается перед запуском сети, обычные аккаунты сохраняются.
TGLock и настройки прокси сохраняются. Это не устраняет ограничение публичного API ID:
для авторизации может понадобиться собственная пара API-параметров.
Ошибки API-параметров при входе показываются явным диалогом; прочие ответы
auth.sendCode также показываются, вместо игнорирования общим обработчиком.

Проверено на ARM64-эмуляторе: обновление поверх сохранённого тестового backend
во всех четырёх слотах, сброс незавершённого тестового входа, отказ переключения
обратно на тестовые серверы, реальный JNI TGLock и восстановление обычного прокси.
APK не содержит флага `debuggable`. Обычный вход по-прежнему требует пригодной
пары Telegram API ID/hash; удаление Test Backend не снимает `API_ID_PUBLISHED_FLOOD`.

## Окружение

- JDK 17.
- Android SDK Platform 36 и Build Tools 36.0.0.
- Android NDK 27.2.12479018 и CMake 3.22.1.
- Gradle 8.13 загружается штатным Gradle Wrapper.
- Rust stable (не ниже 1.88), Cargo и rustup. Нужный Android target устанавливается скриптом.

В `local.properties` укажите `sdk.dir=/абсолютный/путь/к/Android/sdk`.
Переменная `JAVA_HOME` должна указывать на JDK 17.
Локальные пути также можно сохранить в `.local/env.sh`; каталог исключён из Git.

## Сборка

```sh
git clone --branch feature/tglock --recursive --shallow-submodules https://github.com/AndreyZlobin/Telegram.git
cd Telegram
./scripts/build-debug.sh
```

По умолчанию собирается ARM64 debug APK для современного Android-телефона.
Результат: `build/fork-debug/telegram-fork-arm64-v8a-debug.apk`.
Журнал: `build/fork-debug/build.log`.
Сборку другой архитектуры можно выбрать через `BUILD_ABI=x86_64`.
Скрипт передаёт `forkAbi`, чтобы ограничить и компиляцию, и упаковку одной
архитектурой. Без этого параметра сохраняются штатные настройки upstream.
Gradle автоматически собирает `native/tglock-android` и добавляет библиотеку в APK.
Версия ядра закреплена submodule `third_party/tglock` на коммите
`8ce93552433694e72fb74a6b4115f6dd99b62798`; GUI/Tauri не включены.
MIT-лицензия ядра сохранена в исходниках и в assets APK.

Это базовая тестовая сборка с опубликованной upstream тестовой конфигурацией API,
Firebase и подписи. Личный API ID, Firebase и отдельная подпись ещё не настроены.
Вход в аккаунт и push-уведомления не проверялись. Для распространения приложения
нужны собственные значения согласно upstream README.

Свои Telegram API-параметры задаются только в исключённом из Git `local.properties`:

```properties
TELEGRAM_API_ID=ваш_api_id
TELEGRAM_API_HASH=ваш_api_hash
```

Без них остаётся публичная тестовая пара upstream. На проверке сервер возвращал
`API_ID_PUBLISHED_FLOOD`; эта сборка подтверждает интеграцию транспорта, но не
готовность авторизации. Не публикуйте `local.properties` и личные API-параметры.

## Проверки TGLock

```sh
cargo test --manifest-path native/tglock-android/Cargo.toml --lib --locked
./scripts/build-debug.sh :TMessagesProj_App:assembleAfatDebugAndroidTest
```

Instrumentation runner: `org.telegram.tests.TgLockSmokeInstrumentation`.
Он предназначен только для эмулятора без авторизованных аккаунтов и проверяет
настоящий JNI, loopback listener, отказ для чужого адреса, повторный запуск,
остановку и сохранение/восстановление прежнего обычного прокси.
После теста восстанавливаются исходные настройки прокси.

Протокольный probe из upstream не создаёт ключ авторизации и не входит в аккаунт.
Успех такого probe не подтверждает отправку сообщений или загрузку медиа
из авторизованного аккаунта и не гарантирует работу у конкретного провайдера.

## Диагностика сети и переподключение

При смене default network Android TGLock перезапускает свой listener, сбрасывая
старые сокеты и cooldown маршрутов. Аккаунт, выбор TGLock и обычный прокси
сохраняются. Перезапуск выполняется последовательно с переключателем и только
после изменения network handle; начальная регистрация callback его не вызывает.

В ядре пауза после отказов растёт от 30 секунд до 30 минут. На OPPO воспроизведён
немедленный отказ после перехода с мобильной сети на рабочий Wi-Fi; свежий
транспорт на той же сети прошёл batched req_DH для DC1 за 1,9 с. Для DC2 Android-
ядро прошло тот же probe за 1,3 с. Проверки не создают ключ авторизации и не
затрагивают аккаунт.

В текущей мобильной сети на проверке не отвечали все восемь встроенных
WebSocket IPv4-фронтов Telegram; обычный HTTPS был доступен. Сброс cooldown
не делает заблокированные IP доступными. На Wi-Fi OPPO встроенный TGLock
показал подключение без активной VPN-сети.

Для изолированной проверки ядра на Android можно собрать пример
`native/tglock-android/examples/diagnose.rs`: он пишет одноразовый секрет только
в указанный приватный файл и принимает команды `status` / `stop`. Не запускайте
instrumentation-тесты на устройстве с авторизованным аккаунтом.

Для журнала маршрутов самого приложения: `./scripts/build-phone.sh -PforkDiagnostics`.
Флаг выключен по умолчанию. На открытом экране прокси тег logcat `TGLockDiag`
показывает состояние ядра и ошибки маршрутов, без секрета listener, API-пары,
телефона, кодов входа и содержимого сообщений. Само приложение остаётся
недоступным для отладки через JDWP (`debuggable=false`).

В одном процессе OPPO подтверждено: на мобильной сети все маршруты DC2 завершались
таймаутом TCP, `blocked=0`, `unknown_clients=0`, `tunnels=0`; после переключения
на Wi-Fi listener автоматически сменился, стало `route=1`, `tunnels=4`,
`failures=0`, и интерфейс показал подключение. Во время сравнения VPN-сети не было.

## Обновление базы

```sh
git remote add upstream https://github.com/DrKLO/Telegram.git
git fetch upstream master
```

Сначала интегрируйте изменения upstream, затем обновите submodules до версий,
закреплённых в новом коммите. Не используйте `git submodule update --remote`:
это изменит версии зависимостей относительно официальной сборки.
